# clings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `clings`, a rustlings-style C exercise runner in C11 plus 88 exercises with solutions, hints, and CLion integration.

**Architecture:** A single `clings` binary (modules under `src/`, one concern each) reads `info.toml`, compiles and runs one exercise at a time with gcc and sanitizers, tracks progress in `.clings-state.txt`, and offers watch mode. Exercises are plain `.c` files whose checks use a header-only `include/clings.h`. A generated `CMakeLists.txt` block gives CLion one target per exercise; a generated `src/embedded.c` holds pristine copies for `reset`.

**Tech Stack:** C11 with POSIX (fork/exec/pipe/poll/termios/stat), gcc 15 with `-fsanitize=address,undefined`, GNU make, CMake 3.20+, bash + `script` (util-linux) for the integration test.

**Spec:** `docs/superpowers/specs/2026-10-15-clings-design.md`

## Global Constraints

- Runner compiles with `cc -std=c11 -O2 -Wall -Wextra -Wshadow -D_DEFAULT_SOURCE -D_POSIX_C_SOURCE=200809L -I include -I src`; it must build warning-free.
- Exercise compile line (spec §6), verbatim apart from paths: `$CC -std=c11 -Wall -Wextra -Wshadow -g -fsanitize=address,undefined -fno-sanitize-recover=all -I include -I exercises/DIR -o .clings-build/NAME exercises/DIR/NAME.c [helpers...] -lm`. `strict = true` or a solution build appends `-Werror`. `CLINGS_NO_SANITIZE=1` removes the two `-fsanitize*` flags. `CC` env overrides `cc`.
- Exercise run: cwd `exercises/DIR` for both exercise and solution; stdin from `info.toml` `stdin` or `/dev/null`; stdout+stderr merged; cap 64 KiB; timeout 5000 ms; pass iff exit status 0.
- Solutions build to `.clings-build/NAME_sol`.
- Exercise names: `[A-Za-z0-9_]`, max 32 chars, unique. Path is `exercises/DIR/NAME.c`; solution `solutions/DIR/NAME.c`.
- State file `.clings-state.txt`: line 1 `DON'T EDIT THIS FILE!`, line 2 empty, line 3 current name, line 4 empty, then done names one per line. Malformed means fresh.
- Exit codes: 0 success; 1 exercise pending or check failed; 2 usage/environment error.
- Watch poll interval 250 ms; compare `st_mtim` seconds and nanoseconds.
- Every exercise file: comment header, `// TODO` markers, checks after `// Don't change the tests!`, ending `return clings_summary();` when it has checks.
- Every exercise fails unsolved (except `skip_check_unsolved`) and every solution passes with `-Werror`; `./clings dev check` is the gate before any task is called done.
- Commits end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Review Focus

- A state file naming an exercise that no longer exists (renamed in `info.toml`): the name is ignored and progress continues; pinned by `test_state.c` "unknown names ignored" in Task 3.
- An exercise that reads stdin with no `stdin` text in `info.toml`: it must see EOF at once, never block on the terminal; pinned by `test_proc.c` "null stdin gives EOF" in Task 4.
- An exercise whose last output line has no trailing newline: the red failure line must still start on its own line; pinned by `test_exercise.c` "failure line on own line" in Task 6.
- A terminal narrower than the progress bar's minimum: fall back to `Progress: n/N`; pinned by `test_term.c` "narrow width fallback" in Task 5.
- A misspelled exercise name on the command line: exit 2 with the closest names listed, never a crash or a silent no-op; pinned by `test_cli.sh` "unknown name" in Task 7.
